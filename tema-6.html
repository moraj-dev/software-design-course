Repositorios Git y GitHub

El último paso de este curso: llevar tu proyecto a un repositorio con control de versiones. Aprenderás qué es Git, en qué se diferencia de GitHub, y cómo trabajar con commits y ramas de forma colaborativa.

Duración estimada3 horas
NivelIntroductorio–intermedio
EntregableRepositorio propio en GitHub
Objetivos de aprendizaje

Qué vas a lograr en este tema

  • Explicar qué es el control de versiones y por qué es indispensable en desarrollo de software.
  • Diferenciar Git (la herramienta) de GitHub (la plataforma en la nube).
  • Crear un repositorio, realizar commits y trabajar con ramas.
  • Publicar tu proyecto en GitHub y describirlo con un README.
Definiciones clave

Vocabulario base del tema

Control de versiones

Sistema que registra los cambios realizados sobre un conjunto de archivos a lo largo del tiempo, permitiendo volver a versiones anteriores cuando sea necesario.

Git

Sistema de control de versiones distribuido, instalado localmente, que registra el historial de cambios de un proyecto.

GitHub

Plataforma en la nube que aloja repositorios Git y añade herramientas de colaboración: issues, pull requests y revisión de código.

Repositorio

Carpeta de un proyecto cuyo historial de cambios es gestionado por Git.

Commit

Registro puntual de un conjunto de cambios guardados en el historial del repositorio, acompañado de un mensaje descriptivo.

Rama (branch)

Línea de desarrollo independiente dentro de un repositorio, que permite trabajar en una funcionalidad sin afectar el código principal.

El flujo básico de trabajo con Git

git add mueve tus cambios al área de staging; git commit los guarda como un punto del historial local; git push envía esos commits al repositorio remoto en GitHub, donde el resto del equipo puede verlos.

Comandos esenciales

ComandoQué hace
git initConvierte una carpeta en un repositorio Git.
git clone <url>Descarga una copia local de un repositorio remoto.
git statusMuestra el estado actual de los archivos del proyecto.
git add <archivo>Prepara un archivo para ser incluido en el próximo commit.
git commit -m "mensaje"Guarda los cambios preparados con un mensaje descriptivo.
git branch <nombre>Crea una nueva rama de trabajo.
git checkout <rama>Cambia a la rama indicada.
git merge <rama>Combina los cambios de una rama con la rama actual.
git push / git pullEnvía o trae cambios entre el repositorio local y el remoto.

Taller práctico

Publica tu proyecto en GitHub

Individual o en equipo · 90 min
Descargar guía en PDF
  1. Instala Git en tu computador y crea una cuenta gratuita en GitHub, si aún no la tienes.
  2. Crea un repositorio con el nombre de tu proyecto y un README breve que resuma la idea definida en el Tema 3.
  3. Inicializa Git localmente en la carpeta de tu proyecto y realiza tu primer commit.
  4. Crea una rama llamada documentacion y agrega en ella tus historias de usuario del Tema 4 y tus diagramas del Tema 5.
  5. Combina la rama con la rama principal usando git merge.
  6. Publica el repositorio en GitHub con git push y comparte el enlace con tu docente.

Cierre del curso
