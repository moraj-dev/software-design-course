Arquitectura y Ecosistema Tecnológico

Frontend, backend, API, lenguajes de programación, frameworks, librerías, bases de datos: un mapa de las piezas que se combinan para construir una aplicación de software actual y de cómo se comunican entre sí.

Duración estimada2 horas
NivelIntroductorio
EntregableDiagrama de arquitectura simple
Objetivos de aprendizaje

Qué vas a lograr en este tema

  • Diferenciar frontend y backend, y explicar cómo se comunican mediante una API.
  • Reconocer la diferencia entre lenguaje, framework y librería.
  • Ubicar el lugar de una base de datos dentro de la arquitectura de una aplicación.
  • Dibujar un diagrama simple del ecosistema tecnológico de una aplicación propuesta.
Definiciones clave

Vocabulario base del tema

Frontend

La parte de una aplicación con la que interactúa directamente la persona usuaria: interfaces, pantallas, formularios y navegación visual.

Backend

La parte del sistema que corre en el servidor: procesa la lógica de negocio, gestiona datos y responde a las solicitudes del frontend.

API

Interfaz de Programación de Aplicaciones: un conjunto de reglas que permite que dos sistemas (por ejemplo, frontend y backend) intercambien información de forma ordenada.

Framework

Estructura de trabajo predefinida que impone una forma de organizar el código y provee piezas ya construidas para acelerar el desarrollo.

Librería (o biblioteca)

Conjunto de funciones reutilizables que el equipo de desarrollo invoca cuando lo necesita, sin que le imponga una estructura general al proyecto.

Base de datos

Sistema organizado para almacenar, consultar y actualizar la información que una aplicación necesita conservar entre un uso y otro.

Contenido

Cómo se conectan las piezas

Una aplicación web o móvil típica separa lo que la persona usuaria ve (frontend) de lo que ocurre "detrás de bambalinas" (backend). Ambas capas se comunican mediante una API, y el backend a su vez se apoya en una o varias bases de datos para conservar la información entre sesiones.

Cliente (Frontend)

HTML, CSS y JavaScript, a menudo con un framework como React, Vue o Angular. Corre en el navegador o en la app móvil de la persona usuaria.

API

Contrato de comunicación entre cliente y servidor, comúnmente en formato REST o GraphQL, transportando datos en JSON.

Servidor (Backend)

Lógica de negocio escrita en lenguajes como Java, Python, PHP, C# o JavaScript (Node.js), que lee y escribe en la base de datos.

Taller práctico

Diagrama de arquitectura de una app cotidiana

Individual · 60 min
Descargar guía en PDF
  1. Elige una app que uses a diario (por ejemplo, una app de mensajería, de comida o de transporte).
  2. Identifica su frontend. Describe qué pantallas y funciones ve la persona usuaria.
  3. Imagina su backend. Enumera al menos tres tareas que probablemente resuelve el servidor (por ejemplo, autenticar usuarios, calcular una tarifa, guardar un pedido).
  4. Ubica la API. Describe con tus palabras un ejemplo de dato que viaja del frontend al backend y viceversa.
  5. Dibuja el diagrama. Representa con cajas y flechas frontend, API, backend y base de datos.
